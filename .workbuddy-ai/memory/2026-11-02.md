# 2026-11-02

## 新增：缩略图上拖拽直接改页序（用户：能在略缩图上拖拽直接改变页面顺序就更好了）

### 做法

复用 11-01 修合并拖拽时验证过的方案——**自己接管鼠标，不碰 `QDrag`**。

- `side_panel.py` 里新增三个纯函数：`drop_placement` / `is_noop_move` /
  `reorder_indices`（最后这个把"搬哪几行、插到第几行"翻译成整套页序
  `[旧页号...]`，可直接交给 `doc.select()`）
- `ThumbnailList` 加 `mousePressEvent` / `mouseMoveEvent` / `mouseReleaseEvent`，
  超过 `startDragDistance()` 才算拖拽；落点线自己在 `paintEvent` 里画
- 松手时发 `pagesReordered(order)`，由 `MainWindow.reorder_pages()` 真正改文档：
  `begin_change("调整页序")` → `pageops.reorder_pages()` → `end_change()`
- 撤销后停在哪一页按 `order.index(current)` 换算——用户看到的是
  **同一份内容**，不是同一个页码

### 和右键菜单「上移/下移」的关系

两条路都收敛到 `pageops.reorder_pages()`（内部是 `doc.select(order)`，
一次调用完成任意重排），右键菜单保留给不习惯拖拽的人。

### 测试

`ui_smoke.py` 第 27 项「缩略图拖拽能直接改页序」，用 QTest 发真实鼠标事件：

1. 第 1 页拖到第 4 页后面 → 断言文档里**每页的实际文字**变成 P-2/P-3/P-4/P-1/...
2. 最后一页拖到最前面
3. 拖完能撤销，撤销后页序真的退回去
4. 缩略图条目文字与 UserRole 跟着新页序走（否则点第 N 张跳到别的页）
5. 单纯单击不改页序
6. 拖回原地不变，且 `_drag_start`/`_dragging`/`_drop_row` 全部复位

断言看的是**文档实际内容**而不是界面标签：标签可以重编号得很正确，
而底层页面根本没换，那种假绿必须排除。

### 破坏性验证（三种，全部变红）

1. 不识别拖拽 → `AssertionError(['P-1',...,'P-8'])`
2. 落点永远算成原地 → 同上
3. 重排不入撤销栈 → 同上

### 这次踩的坑（教训 44）

写破坏验证脚本时，备份是在**已经打过补丁的文件**上做的，于是"还原"只是把
第一个破坏又写回去，最后连"还原后"也是红的，而脚本还打印"结论：通过"。
第一次就这么白跑一轮。

- 备份必须**只在文件还是原始版本时**做（`if not os.path.exists(backup)`）
- **结论不能只看"破坏时变红"，必须检查"还原后变绿"**，否则"全红"也会被判成功
- 发现"还原后也红"时要先怀疑验证脚本本身，而不是被测代码
