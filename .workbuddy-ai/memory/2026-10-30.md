# 2026-10-30

## 修「合并页面拖动不了」

用户报「在合并页面拖动不了呢」。根因是 `MergePageList.dragEnterEvent` /
`dragMoveEvent` 只认文件 URL（`pdf_paths_from`），而**内部拖拽的 mime 里
没有 URL**，于是 `event.ignore()` —— Qt 认为该位置不能放，松手时连
`dropEvent` 都不派发。表现就是"按下去拖了，松手什么都没发生"。

### 改法

- `dragEnterEvent` / `dragMoveEvent`：PDF 文件 **或** 自己拖自己（`_is_page_drag`）
  都接受；后者再调基类画落点，然后显式 `acceptProposedAction()`
- `dragDropMode` 从 `InternalMove` 改成 `DragDrop`，搬行自己做（`apply_drop`），
  不再依赖 `QAbstractItemView` 的 `event.source() == this` 判断
- **接受 drop 前必须 `setDropAction(Qt.CopyAction)`**：否则 Qt 在
  `drag->exec()` 返回 MoveAction 后会把"当前选中行"再删一遍（它以为视图没搬），
  而那几行已经被搬走 → 整块页面凭空消失。Qt 自己处理图标模式内部拖拽也是这招。
  兜底：`possibleActions()` 里没有 CopyAction 时清掉选中 + `setCurrentRow(-1)`，
  让 Qt 的"移动后清理"找不到目标
- IconMode 下 Qt **不画落点指示线**（那是 ListMode 的行为），
  `setDropIndicatorShown(True)` 等于没开。自己画一条蓝色竖线（`_paint_drop_marker`），
  否则拖的时候零反馈，用户会以为还是拖不动
- 落点规则：光标在格子的**后半**（下方或右方）就插到它后面，否则插到它前面。
  只判"插到悬停项前面"的话，把第 1 格拖到第 2 格 = 原地不动，看起来还是拖不动

### 测试

- 新增 `drop_placement()` / `is_noop_move()` 纯函数，落点换算可单测
  （往前拖、往后拖、多选、拖到末尾、越界）
- 新增界面测试 3 项：落点换算、落点前后半判断、**内部拖拽事件被接受并派发**
  （用 `INTERNAL_MIME` 构造和 Qt 内部同格式的 mime，直接调 dragEnter/dragMove/drop）
- 界面测试 23 → **26 项**，核心 38 项不变
- 破坏性验证：让 `_is_page_drag` 恒返回 False（等价于旧代码），
  `内部拖拽进列表时应该被接受` 立刻变红 ✓
